# 実行時証拠による優先順位付けの成立性調査

- **状態:** 調査中
- **開始日:** 2026-09-09
- **最終更新:** 2026-09-10

## 目的・動機

実行時証拠を脆弱性の検出結果に十分な精度で紐づけ、優先順位付けの改善に使えるかを調査する

このページに初期計画を記録し、調査の進行に合わせて実験・結果・制約・判断を追記する

- **イメージ内の検出結果と実際の実行**
    - スキャナはイメージ内の全パッケージを対象に脆弱性を報告するため、実行されないモジュールの脆弱性も含まれる
- **既存の優先順位付け**
    - CISA KEVとEPSSを使って検出結果に優先順位を付けている
    - これらは全環境共通の指標であり、脆弱なコンポーネントが利用者の環境で実際に動いているかは示さない
- **環境固有の証拠**
    - 脆弱なパッケージのバイナリがプロセスとして実行中か、サービスがポートで待ち受けているか、どの権限で動いているかを調べる
    - これらの証拠を使い、優先順位付けの根拠を説明し、判断の精度を高められるかを検証する

## 方針

- **証拠は優先順位の引き上げにのみ使う**
    - 実行を裏付ける肯定的な証拠があれば、検出結果の優先順位を「今すぐ対応」などへ引き上げられる
    - 証拠がないことを理由に優先順位を下げない
    - 短命なプロセス、再起動、権限不足による観測の欠落を安全の根拠にしない
- **観測の分類**
    - 観測を`confirmed`(確認済み)、`inferred`(推定)、`unknown`(不明)、`unobserved`(未観測)に分類する
    - 待ち受けポートだけでインターネットから到達可能だと判断しない
- **実行時観測機能はオプトイン**
    - 実行時観測機能は明示的に有効化するとDockerホスト上で動作し、procfsとDocker APIから脆弱なパッケージのバイナリのプロセス実行状況・待ち受けポート・実効権限を収集する
    - 実行時観測機能が無効でも、追加権限が不要な標準のイメージスキャンを含め、既存の全機能が従来どおり動作することを条件とする
- **最初の観測対象**
    - Docker Engineのみを対象とし、procfsとDocker APIを使う
    - eBPF、カーネルモジュール、コンテナ内の特権エージェントは使わない
    - Kubernetes側の証拠収集は後続の段階で扱う

## 検証項目

1. **パッケージと実行プロセスの紐づけ精度**
    - 限定された明確な範囲で、パッケージと実行時情報を正確に紐づけられるか
    - 「このプロセスの実行ファイルはこのOSパッケージに由来する」と判断した根拠を説明できるか
2. **不明な情報の安全な扱い**
    - 不明な情報や観測の欠落を安全に扱い、誤って低優先度と判断することを防げるか
3. **運用上の負担**
    - 必要な導入手順・権限・ホスト負荷が、対象利用者の許容範囲に収まるか
4. **KEV・EPSSに追加する価値**
    - KEV・EPSSだけの場合に比べ、実行時証拠によって対応すべき検出結果を有用な形で絞り込めるか
5. **実行時観測機能が無効な場合の動作**
    - 実行時観測機能を無効にしても既存の全機能が完全に維持されるか

5つすべてを継続の条件とし、満たせない場合は実行時証拠の機能を見送る

## 今回の対象外

- **Kubernetesの証拠収集**
    - Kubernetes側の証拠収集は、本調査でDocker Engineでの成立性を確認した後に着手する
    - 最初に既存の読み取り専用Kubernetes adapterから得られるcontainerPort・Serviceの宣言による待ち受けの見込みとsecurityContextによる実効権限の見込みを、実行時観測機能や追加権限なしの`inferred`証拠として扱う
    - 次にDocker向けの初期実装の後続として、Kubernetes利用者からの需要確認を条件に、オプトインのDaemonSet観測で`confirmed`証拠を収集する

## 検証方法(初期計画)

- **プロセスとパッケージの所有関係**
    - Dockerホスト上の実コンテナで検証する
    - procfsからプロセスを列挙し、実行ファイルをインストール済みパッケージに紐づける
    - dpkgの所有情報などを使い、OSパッケージから着手する
- **ポートと権限**
    - procfsとDocker APIから待ち受けポートと実効権限を収集する
    - 待ち受けポートの観測とインターネットからの到達可能性の判断を区別する
- **精度と運用コスト**
    - 紐づけの精度、失敗パターン、収集のオーバーヘッドを測定する
    - 観測に必要な導入手順と権限を記録する
- **紐づけられないケース**
    - 更新時に削除されたバイナリ、ライブラリとして読み込まれる言語ランタイムの依存関係、distrolessイメージを検証する
    - 紐づけられないケースは推測で補わず、明示的に`unknown`として記録する
- **優先順位付けと既存機能の維持**
    - 肯定的な証拠がKEV・EPSSに加えて有用な絞り込みにつながるかを評価する
    - 不明・未観測の情報によって優先順位が下がらないことを検証する
    - 実行時観測機能が無効な場合に既存の全機能が維持されることを検証する
