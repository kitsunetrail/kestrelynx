# 実行環境の一覧を KestreLynx のイメージから切り離す開発

- **状態:** 実装済み(一覧の公開と読み込み、依存パッケージの更新、使わなくなった作業用イメージの削除、稼働環境での起動を確認)
- **開始日:** 2026年11月18日
- **最終更新:** 2026年11月18日

## 目的

実行環境の一覧を KestreLynx のイメージから切り離し、イメージを取り直さなくても、新しい実行版と系列を使えるようにする。

言語パッケージの更新に使う実行版や公式イメージを定める実行環境の一覧は、KestreLynx のイメージに同梱されている。
そのため、週に1回の一覧の更新を取り込むたびに、利用者は KestreLynx のイメージを取り直す必要がある。

次の表は、利用者が KestreLynx のイメージを取り直さず、実行環境の一覧が古いままになった場合の、言語パッケージの更新への影響を示す。
最初の2行は一覧が古いことで生じる支障を、最後の行は一覧が古くてもサポート終了の判定が切り替わることを示す。

| 一覧が古いままの場合 | 利用者への影響 |
|---|---|
| 作業用イメージが古いままになる | Node.js・Python・Go 本体と OS のライブラリに入った修正が入らない |
| Go の実行版が古い | 一覧より新しいパッチ版を要求する `go.mod` を更新できない |
| 一覧にあるサポート終了日を迎える | 一覧が古くても、現在時刻との比較でサポート終了に切り替わる |

利用時の動作は[実行環境の一覧の更新](../documentation/remediation-worker-logic.md#runtime-table-updates)にまとめている。

## 方針

- 実行環境の一覧を KestreLynx のイメージとは別に公開する
- 起動時と各サイクルの開始時に、公開されている一覧を読み込む
- 読み込んだ一覧が検査を通り、今の一覧より新しければ置き換える
- 使わなくなった作業用イメージのうち、KestreLynx が自分で取得したものだけを削除する

## 決定事項

### 一覧の公開と読み込み

<h4>決めたこと</h4>

一覧を KestreLynx のイメージとは別に、GHCR へ1つのファイルとして公開する。
KestreLynx は起動時と各サイクルの開始時に読み込み、サイクルの途中では一覧を変えない。

<h4>詳細</h4>

公開先は `ghcr.io/kitsunetrail/kestrelynx-runtimes` とする。
週次の一覧の更新の PR をマージしたときに公開する。

設定は[作業用コンテナの設定](../documentation/configuration.md#remediation-worker)、通信先は[実行環境の一覧の取得](../documentation/outbound-communication.md#runtime-table-download)にまとめている。

### 読み込んだ一覧に置き換える条件

<h4>決めたこと</h4>

読み込んだ一覧が検査を通り、今の一覧より新しければ、一覧を丸ごと置き換える。

<h4>詳細</h4>

使う一覧は次のように決める。

| 状況 | 使う一覧 |
|---|---|
| 最初の読み込みが終わる前 | 同梱の一覧 |
| 読み込んだ一覧が検査を通り、今の一覧より新しい | 読み込んだ一覧で全体を置き換える |
| 読み込んだ一覧が今の一覧より新しくない | 今使っている一覧 |
| 読み込んだ一覧が検査に通らない | 今使っている一覧 |
| 読み込みを止めている | 同梱の一覧 |

読み込んだ一覧は、次の条件を満たすことを確かめる。

- 大きさと件数が上限内にあること
- イメージが Docker Hub の公式の `node`・`python`・`golang`・`gradle` であること
- digest と版の書き方が正しいこと
- 系列と版が合っていること
- 更新時刻が現在より24時間以上先でないこと

使っている KestreLynx が対応していない行は、その行だけを使わない。

### KestreLynx を更新しなくても反映される変更

<h4>決めたこと</h4>

実行版や公式イメージの更新だけでなく、新しい系列も、一覧の更新だけで使えるようにする。

<h4>詳細</h4>

変更ごとに、KestreLynx の更新が必要かを次の表に示す。

| 変更 | KestreLynx の更新 |
|---|---|
| 既存の系列の実行版と公式イメージ | 不要 |
| pip の版 | 不要 |
| サポート終了日 | 不要 |
| 新しい系列（Node.js・Python・Go） | 不要 |
| Gradle の新しい版と JDK の組 | 不要 |
| Gradle のプラグイン（Spring Boot など）への対応 | 必要 |
| `.nvmrc` の `lts/<新しい名前>` の解釈 | 必要 |
| 新しい言語 | 必要 |

### 新しい系列を作業用コンテナで使うための変更

<h4>決めたこと</h4>

作業プログラムは実行環境の一覧を持たず、実行環境の名前から言語と系列を読み取る。

<h4>詳細</h4>

作業プログラムは、作業用コンテナの中でパッケージマネージャーを実行する KestreLynx のプログラムである。

これまでは作業プログラムも実行環境の一覧を持ち、指示された実行環境がその一覧にあることを確かめていた。
その一覧は KestreLynx のイメージを作ったときのものなので、後から一覧に加わった系列を使えなかった。

実行環境の名前では、`node24` が Node.js 24、`gradle9.8.2-jdk21` が Gradle 9.8.2 と JDK 21 を表す。
実際に動いた版が指示された版と同じであることは、これまでどおり確かめる。

### 署名

<h4>決めたこと</h4>

一覧には署名を付けない。
読み込んだ一覧は、イメージが Docker Hub の公式イメージであることを検査するので、一覧が書き換えられても、公式イメージ以外は動かない。

### 使わなくなった作業用イメージの削除

<h4>決めたこと</h4>

Docker では、一覧が置き換わって使わなくなった作業用イメージを削除する。
削除するのは、KestreLynx が自分で取得したイメージだけである。

<h4>詳細</h4>

次の場合はイメージを削除しない。

| 場合 | 扱い |
|---|---|
| 利用者が同じイメージにタグを付けている | 削除しない |
| 利用者が同じイメージを先に取得していた | 削除しない |
| コンテナが使っている | 削除せず、次のサイクルでもう一度試す |

強制削除はしない。
Kubernetes では削除せず、ノードに任せる。

利用時の条件は[使わなくなった作業用イメージの削除](../documentation/remediation-worker-logic.md#worker-image-cleanup)にまとめている。

## 検証方法

- 作業プログラムから一覧を外しても、これまでと同じように npm・pnpm・uv・pip・Go・Gradle の依存パッケージを更新できることを、手元の Docker で作業用コンテナを動かして確かめる
- 一覧を GHCR に公開し、KestreLynx が認証なしで読み込めることを確かめる
- Docker の2種類のイメージ保存方式で、使わなくなった作業用イメージが削除され、利用者のイメージが残ることを手元で確かめる
- 本番運用環境（Docker）と検証用のホスト（Kubernetes）の KestreLynx を更新し、起動時のログで使っている一覧を確かめる

## 検証結果

### 依存パッケージの更新

Docker 29.1.3 で依存パッケージの更新を確かめた。

| 対象 | 含めた系列 | 結果 |
|---|---|---|
| npm・pnpm・uv・pip・Go の更新 | Node.js 22・24・26、Python 3.11〜3.15、Go 1.26・1.27 | 61ケースすべて成功 |
| Gradle の更新 | Gradle 8.14.6・9.8.2 | 3ケースすべて成功 |

### 一覧の公開と読み込み

一覧を GHCR に公開でき、公開直後から認証なしで読み込めた。
読み込んだ一覧は106行すべてが検査を通った。

### 使わなくなった作業用イメージの削除

Docker 29.1.3（containerd の image store）と Docker 29.10.0（従来の方式）で削除を確かめ、結果は同じだった。

| 場合 | 結果 |
|---|---|
| KestreLynx が自分で取得したイメージ | 削除された |
| 取得の後で利用者がタグを付けたイメージ | 残った |
| 停止中のコンテナが使っているイメージ | 残り、コンテナを削除した後のサイクルで削除された |

containerd の image store では、digest を指定して削除するとタグも一緒に消えたため、タグが付いたイメージは削除しないことにした。

### 稼働環境での起動

本番運用環境の Docker と、検証用のホストの Kubernetes で KestreLynx を更新し、起動時のログを確認した。

| 記録された項目 | 値 |
|---|---|
| 一覧の出どころ | 同梱 |
| 更新時刻 | `2026-11-16T11:58:54Z` |
| 行数 | 106行 |

公開中の一覧は同梱の一覧と同じ内容なので、置き換えは起きていない。

| 環境 | 最初のサイクル |
|---|---|
| 本番運用環境（Docker） | 完了、警告・エラーのログは0件 |
| 検証用のホスト（Kubernetes） | 完了、警告・エラーのログは0件 |

## 既知の制約

- 一覧を公開する前のテストは最新の KestreLynx で行うため、古い KestreLynx が新しい系列で正しく動くかは確かめていない
    - 動かなかった場合は、その更新は失敗になり、PR は作られない
