# Slackの稼働時の使用状況の表示

Sensorの情報がある場合、パッケージに使用状況を表示します。
Sensorは、稼働中のコンテナでパッケージが使われているかを観測する仕組みです。

使用判定や観測の限界は[稼働時の使用状況](runtime-usage.md)を参照してください。

## 使用状況のラベル {#usage-labels}

使用状況のラベルは、カードに表示するパッケージについて、次の状態を示します。

| 表示 | 意味 |
| --- | --- |
| `▶ 使用中` | 使用を確認したパッケージ |
| `▷ 使用が確認されない` | 観測期間内に使用を確認していないパッケージ |
| `▷ 稼働時の使用状況を判定できない` | 判定に必要な情報を利用できないパッケージ |

使用が確認されないことは、未使用であることを意味しません。
判定できない場合は、括弧内に理由を表示します。

次の例は、別々のパッケージに付く使用状況の行を抜粋したものです。

```text
使用状況: ▶ 使用中 (実行中)
使用状況: ▷ 使用が確認されない
使用状況: ▷ 稼働時の使用状況を判定できない (Sensorの報告なし)
```

使用状況の表示は、通知の場所とカードの種類によって異なります。

| 表示する場所 | 表示する内容 |
| --- | --- |
| チャンネルの詳細カード | 使用中の場合に、使用状況と観測根拠を表示 |
| チャンネルの簡略カード | 使用中の場合に、動作を括弧内に短く表示 |
| スレッドの詳細カード | 使用中・使用が確認されない・判定できない状態を表示 |
| 全体レポートとスレッドの低優先度 | 個別カードを出さず、区分の件数に使用中の件数を添える |
| チャンネルの差分にある低優先度 | 新規検出やCVE追加を簡略カードで表示 |

チャンネルの全体レポートでは、低優先度のうち使用中の件数を見出しの末尾に添えます。
次の例では、低優先度2件のうち1件が使用中です。

```text
🔕 低優先度 (2件) — イメージ2件で所見2件、悪用の兆候なし (KEV未掲載、EPSSはしきい値未満) · ▶ 使用中1件
```

スレッドでは、同じ件数を次のように別の行で示します。
どちらの場所でも、使用中が0件なら使用中の件数は表示しません。

```text
🔕 低優先度 (2件) — 悪用の兆候なし
▶ 低優先度のうち使用中: 1件
```

判定できない理由のうち、Sensorからの情報の取得と、観測の準備・継続に関する表示は次のとおりです。

| 理由の表示 | 意味 |
| --- | --- |
| `Sensorの報告なし` | Sensorの観測結果のファイルがまだない |
| `Sensorの報告が古い` | Sensorの報告や対象コンテナの確認から時間がたち、使用が確認されないと判断できない |
| `証拠が無効` | Sensorの観測結果を読み取り、内容を検証する処理に失敗している |
| `Sensorの隔離失敗` | Sensorに読み取り以外の操作を制限する設定ができず、観測を始めていない |
| `権限不足` | Sensorがコンテナのプロセス情報やファイルを読む操作を拒否されている |
| `索引が未構築` | パッケージとファイルを対応付けるための準備ができていない |
| `ワーカーの処理が停滞` | 対象コンテナを調べる処理が制限時間内に終わっていない |
| `証拠の切り詰め` | 読み取り量などの上限に達し、観測に必要な情報の一部を取得できていない |
| `証拠が不完全` | 観測結果の一部を利用できず、その部分での使用を確認できない |

コンテナと観測結果の対応に関する表示は次のとおりです。

| 理由の表示 | 意味 |
| --- | --- |
| `コンテナの世代が未確認` | 観測結果が、現在のコンテナの起動状態とスキャン対象のイメージに対応するか確認できない |
| `コンテナが未観測` | 対象コンテナについて、判定に使える観測結果がない |

パッケージの管理情報や、そのファイルとの対応に関する表示は次のとおりです。

| 理由の表示 | 意味 |
| --- | --- |
| `パッケージデータベースの解析失敗` | コンテナ内のパッケージ管理情報を解析できない |
| `パッケージデータベースなし` | コンテナ内に、利用できるパッケージ管理情報が見つかっていない |
| `パッケージデータベースのエラー` | パッケージ管理情報の読み取りか解析に失敗している |
| `パッケージデータベースが未対応` | コンテナ内のパッケージ管理情報が、Sensorの対応していない形式 |
| `このパッケージのファイル一覧なし` | パッケージ管理情報から、そのパッケージに属するファイルの一覧を取得できない |
| `所有元が複数` | 観測したファイルが複数のパッケージに属し、どのパッケージの使用か特定できない |
| `ファイルが置き換えられている` | 観測したファイルが削除・置換され、パッケージとの対応を確定できない |
| `バージョン不一致` | Sensorが使用を確認したパッケージの版が、スキャンで検出した版と異なる |

言語パッケージとの対応に関する表示と、理由を特定できない場合の表示は次のとおりです。

| 理由の表示 | 意味 |
| --- | --- |
| `エコシステムの対応付けなし` | その言語パッケージの種類について、使用判定に使う実行環境が対応付けられていない |
| `バイナリのパス不明` | パッケージの使用判定に必要な実行ファイルの場所が、スキャン結果にない |
| `不明` | 判定できない理由を特定できない |

## 観測根拠の表示 {#runtime-evidence}

使用中の詳細カードは、使用を確認した動作と、その観測に関する情報を示します。
次の例では、nginxの実行を根拠に使用中と判定しています。

```text
使用状況: ▶ 使用中
観測根拠: 実行中 /usr/sbin/nginx
公開状態: 全インターフェースに公開 · 高い権限で実行 · 最終確認06-24 09:00
```

例の各行は、次の内容を示します。

| 行 | 読み方 |
| --- | --- |
| `使用状況:` | カードのパッケージを使用中と判定した結果 |
| `観測根拠:` | 使用を確認した動作とプログラム |
| `公開状態:` | ポートの公開範囲、実行時の権限、観測の最終確認時刻 |

これらの情報は、そのパッケージを使用している1つのコンテナの観測から表示します。
複数のコンテナで使用している場合は、公開範囲が広いものを優先し、同じ範囲なら権限が高いものを選びます。

観測根拠には、定期的な確認で見つけた実行状態と、起動・読み込みの出来事として捉えた動作があります。
プログラムのパスの前に付く文言は、次の意味です。

| 表示 | 意味 |
| --- | --- |
| `実行中` | 定期的な確認で、そのパッケージのファイルが実行中だった |
| `読み込んだプログラム` | 定期的な確認で、そのパッケージのライブラリを読み込んだプログラムが動いていた |
| `実行を観測` | そのパッケージのファイルが実行される出来事を捉えた |
| `ライブラリ読み込みを観測` | そのパッケージのライブラリが読み込まれる出来事を捉えた |
| `組み込み先の実行中バイナリ` | 定期的な確認で、言語パッケージを組み込んだ実行ファイルが動いていた |
| `バイナリの実行を観測` | 言語パッケージを組み込んだ実行ファイルが起動する出来事を捉えた |
| `稼働中の実行環境` | 定期的な確認で、言語パッケージに対応する実行環境が動いていた |
| `実行環境の実行を観測` | 言語パッケージに対応する実行環境が起動する出来事を捉えた |

実行環境を根拠とする表示は、その環境に対応する言語パッケージをまとめて使用中とみなした結果です。
個々のパッケージの読み込みを確認した結果ではありません（[使用判定の説明](runtime-usage.md)）。

`実行中`も観測した時点の状態を示すため、通知を読んでいる時点で動いているとは限りません。
観測した時刻は、`最終確認`で確認できます。

複数のプログラムで異なる動作を確認し、動作とプログラムを対応付けられない場合は、次のように一覧を分けます。

```text
観測根拠: 実行中; ライブラリとして読み込み済み; プロセス: /usr/bin/helper, /app/server
```

この例は、実行とライブラリの読み込みを確認したことを示します。
`プロセス:`は観測したプログラムの一覧で、前に並ぶ動作と順番に対応するものではありません。

公開範囲・権限・最終確認は、利用できる情報を`公開状態:`の1行にまとめて表示します。
それぞれの表示の意味は次のとおりです。

| 表示 | 意味 |
| --- | --- |
| `全インターフェースに公開` | 使用を確認したプログラムのポートを、ホストの全インターフェースに公開 |
| `ループバックのみに公開` | 使用を確認したプログラムのポートを、ホスト自身から接続するアドレスだけに公開 |
| `待ち受け中 (未公開)` | 使用を確認したプログラムが、ホストにポートを公開せずに接続を待ち受けている |
| `高い権限で実行` | 使用を確認したプログラムが、下記の強い権限のいずれかを持つ |
| `最終確認` | 表示している観測を最後に確認した時刻 |

`高い権限で実行`は、次のいずれかに該当する場合に表示します。

- 特権モードのコンテナで実行
- システム管理やファイルアクセス制限の回避などに使える強い権限を持つ
- ホストとユーザー権限を分離していないrootのプロセスとして実行

公開範囲が分からず、権限の情報がある場合は、`権限:`の行に権限と最終確認を表示します。
どちらも表示できない場合は、`最終確認:`の行に時刻だけを表示します。

## 通知オフの表示 {#muted-display}

通知オフは、修正版がなく、7日以上使用が確認されないパッケージを個別に通知しない機能です。
この機能を有効にした場合に適用し、今すぐ対応やEOLのパッケージは対象にしません。

通知オフのパッケージは、チャンネル・スレッド・差分の個別カードから除き、件数で示します。
件数は非表示にしたカードに相当する数で、同じイメージ名とパッケージの組み合わせでも、版や修正状態が異なれば別件です。

次の例では、通知オフの1件が、稼働時の使用状況の「使用が確認されない1件」にも含まれています。

```text
🔇 通知オフ — 修正版がなく7日以上使用が確認されない: 1件
🔎 稼働時の使用状況: ▶ 使用中1件 · 使用が確認されない1件 · 判定できない0件
```

今回のスキャンで通知オフと判定したパッケージは、ほかの件数で次のように扱います。

- `優先度:`の件数と、現在の未解決の優先度件数から除外
- トリアージ無効時の現在の未解決の深刻度別件数から除外
- 稼働時の使用状況では「使用が確認されない」に含めるため、通知オフの件数と重複

スキャンに失敗すると、前回のスキャンの記録を使う場合があります。
その記録について今回の通知オフを判定できない場合は、現在の未解決の優先度件数に含めます。

スキャン失敗だけを理由に、通知再開の表示を出すことはありません。

通知を再開したパッケージには、次のように変化を表示します。

```text
変化: ↩️ 通知を再開 (使用中になった)
```

通知再開の理由と、それぞれの表示は次のとおりです。

| 再開の理由 | 表示 |
| --- | --- |
| パッケージの使用を確認した | `変化: ↩️ 通知を再開 (使用中になった)` |
| パッケージが今すぐ対応に該当する | `変化: ↩️ 通知を再開 (今すぐ対応)` |
| パッケージに修正版がある | `変化: ↩️ 通知を再開 (修正版あり)` |
| パッケージがサポート終了となった | `変化: ↩️ 通知を再開 (サポート終了(EOL)となった)` |
| 使用状況を判定できないか、必要な観測期間に満たない | `変化: ↩️ 通知を再開 (観測不足)` |
| パッケージの修正状態が通知オフの対象から外れた | `変化: ↩️ 通知を再開 (対象外の状態)` |

通知を再開したパッケージに修正版の公開や優先度の上昇などもある場合、KestreLynxは[その変化の表示](slack-package-display.md#package-change-labels)を優先します。

通知オフの条件と再開理由は[修正版がない所見の通知オフ](runtime-usage.md#muting-findings-without-a-fix)を参照してください。
